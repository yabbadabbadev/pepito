# Dependency Upkeep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the msw 2/3 peer contract explicit and CI-proven, auto-merge safe Dependabot minor updates, and track the newest Node LTS from `.nvmrc` through a scheduled PR.

**Architecture:** Two independent PRs off `main`. PR 1 widens the msw peer range, regenerates the service-worker script with a CI meter that catches staleness, and adds a second test run against msw 2.15.0 inside the existing `quality` job. PR 2 extends the Dependabot auto-merge workflow to minors with a `peerDependencies` guard, and adds a scheduled workflow that opens an `.nvmrc` PR for the newest LTS.

**Tech Stack:** GitHub Actions (YAML), npm 11 lockfile, `dependabot/fetch-metadata`, `gh` + `jq`, msw 3.0.4 / 2.15.0, Vitest 5 browser mode.

**Spec:** `docs/superpowers/specs/2026-11-14-dependency-upkeep-design.md`

## Global Constraints

- English everywhere: code comments, docs, commit messages, workflow comments.
- Never commit on `main`; every change lands through a branch and a PR.
- `peerDependencies.msw` is exactly `^2.15.0 || ^3.0.0`; `devDependencies.msw` stays `^3.0.4`.
- Target Node LTS is exactly `26.13.1` for this change.
- No new secrets and no long-lived credentials: `GITHUB_TOKEN` only.
- Actions are pinned by full commit SHA with a version comment; use the existing `actions/checkout` pin `3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`.
- Do not use a matrix for the msw 2 leg: it would rename the required `quality` check.
- Use npm scripts for project commands; `npx msw init` and `npx playwright install` are the allowed one-offs.
- Oxlint 0 warnings, Prettier clean, strict TS, 90/90 coverage unchanged.
- Measured vs assumed stays labelled in every doc you touch.

## Review Focus

- A consumer still on msw 2 installs the new pepito and its tests keep passing — pinned by the new CI leg in Task 2.
- A consumer on msw 2 reads the README start-options example: the option has a different name there — pinned by the note in Task 3.
- A Dependabot minor rewrites `peerDependencies` — pinned by the guard dry-run in Task 4; the live run only happens on the first bot PR after merge.
- A stale `public/mockServiceWorker.js` passes the suite silently — pinned red-then-green by the meter in Task 1.
- The `.nvmrc` workflow runs again while its PR is open, or the LTS lookup returns nothing — pinned by the branch-per-version logic and the empty-version guard in Task 5.


- [ ] **Step 2: Replace the workflow content**

```yaml
name: dependabot-automerge
on: pull_request

permissions:
  contents: write
  pull-requests: write

jobs:
  automerge:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    if: github.actor == 'dependabot[bot]'

    steps:
      - name: Dependabot metadata
        id: metadata
        uses: dependabot/fetch-metadata@25dd0e34f4fe68f24cc83900b1fe3fe149efef98 # v3.1.0
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}

      # The published peer range is the library's contract. A Dependabot
      # minor bump can rewrite it with no code change (measured: PR #55
      # moved msw from ^2.15.0 to ^3.0.4), which would narrow what pepito
      # accepts inside a pepito patch release. Those PRs always wait for a
      # human. Any failure reading the two files also defers to a human.
      - name: Does the PR change peerDependencies?
        id: peers
        run: |
          set -uo pipefail
          if ! base="$(gh api "repos/$REPO/contents/package.json?ref=$BASE_SHA" -q .content | base64 -d | jq -S .peerDependencies)"; then
            echo "changed=true" >> "$GITHUB_OUTPUT"
            echo "Could not read the base package.json; leaving the PR for a human." >&2
            exit 0
          fi
          if ! head="$(gh api "repos/$REPO/contents/package.json?ref=$HEAD_SHA" -q .content | base64 -d | jq -S .peerDependencies)"; then
            echo "changed=true" >> "$GITHUB_OUTPUT"
            echo "Could not read the head package.json; leaving the PR for a human." >&2
            exit 0
          fi
          if [ "$base" = "$head" ]; then
            echo "changed=false" >> "$GITHUB_OUTPUT"
          else
            echo "changed=true" >> "$GITHUB_OUTPUT"
            echo "peerDependencies changed; leaving the PR for a human." >&2
          fi
        env:
          REPO: ${{ github.repository }}
          BASE_SHA: ${{ github.event.pull_request.base.sha }}
          HEAD_SHA: ${{ github.event.pull_request.head.sha }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Approve and enable auto-merge for patch and minor updates
        if: >-
          (steps.metadata.outputs.update-type == 'version-update:semver-patch' ||
          steps.metadata.outputs.update-type == 'version-update:semver-minor') &&
          steps.peers.outputs.changed == 'false'
        run: |
          gh pr review --approve "$PR_URL"
          gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### Task 5: scheduled `.nvmrc` PR for the newest Node LTS

**Files:**

- Create: `.github/workflows/nvmrc.yml`
- Modify: `.nvmrc`

**Interfaces:**

- Consumes: the existing `actions/checkout` SHA pin.
- Produces: branch name `chore/nvmrc-<version>`, label-free PRs titled `build: track Node.js LTS <version>`, and `.nvmrc` containing `26.13.1`.

- [ ] **Step 1: Create the workflow**

```yaml
name: nvmrc

# Keeps .nvmrc on the newest Node.js LTS line. Opens a PR and stops there:
# the CI run it triggers is the proof, and a human merges. GITHUB_TOKEN
# only; no secret. The PR lands in `action_required` like release-please's:
# a human approves the run, the checks prove it, a human merges.
on:
  schedule:
    # Mondays at 06:00 UTC.
    - cron: '0 6 * * 1'
  workflow_dispatch:

permissions:
  contents: write
  pull-requests: write

concurrency: nvmrc

jobs:
  update:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1

      - name: Resolve the newest LTS
        id: lts
        run: |
          version="$(curl -fsSL https://nodejs.org/dist/index.json \
            | jq -r '[.[] | select(.lts != false)][0].version' \
            | sed 's/^v//')"
          if [ -z "$version" ] || [ "$version" = 'null' ]; then
            echo "Could not resolve the newest LTS from nodejs.org" >&2
            exit 1
          fi
          echo "version=$version" >> "$GITHUB_OUTPUT"

      - name: Decide whether an update is needed
        id: check
        run: |
          current="$(tr -d '[:space:]' < .nvmrc)"
          if [ "$current" = "${{ steps.lts.outputs.version }}" ]; then
            echo "needed=false" >> "$GITHUB_OUTPUT"
            echo ".nvmrc already tracks $current"
          else
            echo "needed=true" >> "$GITHUB_OUTPUT"
            echo ".nvmrc $current -> ${{ steps.lts.outputs.version }}"
          fi

      - name: Open the PR
        if: steps.check.outputs.needed == 'true'
        run: |
          set -euo pipefail
          version="${{ steps.lts.outputs.version }}"
          branch="chore/nvmrc-$version"
          git config user.name 'github-actions[bot]'
          git config user.email '41898282+github-actions[bot]@users.noreply.github.com'
          git switch -c "$branch"
          printf '%s\n' "$version" > .nvmrc
          git add .nvmrc
          git commit -m "build: track Node.js LTS $version"
          git push --force origin "$branch"
          # A push made with GITHUB_TOKEN does not trigger workflows, not even
          # pull_request synchronize on the bot's own branch. Closing older
          # PRs and opening a fresh one per version is what gets CI to run.
          gh pr list --state open --json number,headRefName,isCrossRepository \
            | jq -r --arg current "$branch" '.[] | select(.isCrossRepository == false) | select(.headRefName | startswith("chore/nvmrc-")) | select(.headRefName != $current) | .number' \
            | xargs -r -n1 gh pr close
          gh pr create \
            --base main \
            --head "$branch" \
            --title "build: track Node.js LTS $version" \
            --body "Newest Node.js LTS is \`$version\` ([release notes](https://nodejs.org/en/blog/release/v$version)). CI on this PR is the proof; a human merges."
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```
