# Dependency upkeep: msw 3, minor auto-merge, Node LTS tracking

Short design for three maintenance changes approved on 2026-11-14.

## Intent

Three independent maintenance jobs land together because they share one
concern: the package's dependency contract should stop depending on manual
care. `msw` moved to 3.x and the suite is green, but the published peer range,
the service-worker script and the docs did not move with it. Dependency PRs
still need a human for every minor. `.nvmrc` still needs a human for every
Node release.

## Measured context

- The full suite passes on `msw@3.0.4` (71/71) and on `msw@2.15.0` (71/71,
  same source, temporary copy). `typecheck`, `lint` and `format:check` are
  green on 3.0.4.
- The five events `src/msw-events.ts` listens to exist unchanged in
  `node_modules/msw/lib/_chunks/interceptor-source.d.ts`: request events carry
  `{ requestId, request }`, response events carry
  `{ requestId, request, response }` plus `isMockedResponse`. That is reading
  the installed artifact this package runs against, so it counts as measured
  under this repo's label rule.
- Dependabot changed `peerDependencies.msw` from `^2.15.0` to `^3.0.4` in PR
  #55 (commit `2e3b6a6`), which was merged manually. Shipping that unchanged
  would exclude every consumer on msw 2 without a pepito major.
- `public/mockServiceWorker.js` is still the script generated by `2.15.0`
  (`PACKAGE_VERSION = '2.15.0'`); msw 3 ships a substantially different one.
  The integrity check warns through `console.warn`, which the default reporter
  does not surface, so nothing went red.
- `README.md:118` documents `onUnhandledRequest`, renamed to
  `onUnhandledFrame` in 3.0.
- `dependabot/fetch-metadata` reports the highest semver change in a grouped
  PR, so a group containing a major cannot match a patch-or-minor condition.
- The newest Node LTS at design time is `26.13.1` ("Lithium", bundled npm
  11.20.0), read from `https://nodejs.org/dist/index.json`.
- The msw 2 CI swap command was measured: after `npm ci`,
  `npm i --no-save msw@2.15.0` keeps the rest of the locked tree intact
  (playwright stays 1.65.0, `vite` is present) and the suite passes 71/71
  after `npx msw init public --save`.

## Goals

1. `pepito` installs against both msw 2.15+ and msw 3.x, and CI proves both.
2. Dependabot minor updates merge without a human when they are safe; a change
   to the published peer contract never does.
3. `.nvmrc` tracks the newest Node LTS through a PR a human still merges.

## Non-goals

- Re-measuring the millisecond timings in `measured-foundations.md`. The
  suite pins the semantics; the timings stay labelled as measured on 2.15.0.
- Dropping msw 2 from the supported range (that would be pepito 0.4.0).
- Auto-merging the Node LTS PR.
- Adding an `engines` field to `package.json`.

## Anti-goals

- A peer range that quietly narrows in a patch release.
- A green suite that hides a stale service-worker script.
- A second dependency bot (Renovate) doing what Dependabot already does.

## Part 1 — msw 3 support (release `0.3.1`)

### Approaches

| Approach                                                    | Trade-off                                                                        | Verdict                                            |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------- |
| Widen the peer to `^2.15.0 \|\| ^3.0.0` and test both in CI | One extra test run (~7 s measured locally); keeps every existing consumer        | **Picked**                                         |
| Commit to 3.x only, publish a breaking `0.4.0`              | Simpler CI; abandons consumers on msw 2 and burns a breaking release for nothing | Rejected: the event API did not change             |
| Widen the peer without a second CI leg                      | Cheapest today; the msw 2 claim rots silently on the next refactor               | Rejected: an unproven claim is worse than no claim |

### Design

- `package.json`: `peerDependencies.msw` becomes `"^2.15.0 || ^3.0.0"`. The
  devDependency stays `^3.0.4`, so the main leg always runs the newest
  supported major.
- Regenerate `public/mockServiceWorker.js` with `npx msw init public --save`
  against msw 3.0.4.
- `README.md`: the start-options example uses `onUnhandledFrame: 'error'`,
  with one line noting that msw 2 spells the same option
  `onUnhandledRequest`.
- `.agents/docs/references/measured-foundations.md`: new final section
  recording the msw 3 verification (same events and payloads; suite green on
  both majors; the worker script was stale; the renamed option). The header
  line that pins `msw@2.15.0` gains a pointer to that section rather than
  losing its provenance.
- `ci.yml`: after the coverage step, a new step swaps the installed major
  (`npm i --no-save msw@2.15.0`), regenerates the worker for that version
  (`npx msw init public --save`) and runs `npm test`. It lives inside the
  existing `quality` job on purpose: a matrix would rename the required check
  (`quality (msw 2)`), which would need a branch-protection edit.
- No change under `src/`. That is the evidence that the major did not break
  the contract.
- The PR is titled `fix: support msw 3 alongside msw 2` so release-please
  publishes `0.3.1`; the widening is a correction to the published contract,
  not a new feature.

## Part 2 — auto-merge minor Dependabot PRs

### Approaches

| Approach                                                      | Trade-off                                                                                        | Verdict         |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------- |
| Patch + minor, blocked when the PR changes `peerDependencies` | Automates almost everything; the one contract-breaking path stays human                          | **Picked**      |
| Patch + minor with no guard                                   | Simple; a minor bump of msw/vitest can narrow the published peer range in a pepito patch release | Rejected        |
| Exclude msw and vitest by name                                | Safe, but those two live in the `testing` group, so it makes most testing updates manual         | Rejected: blunt |

### Design

- `dependabot-automerge.yml`: the merge step condition becomes
  update-type in (`semver-patch`, `semver-minor`) **and** the PR does not
  change `peerDependencies`.
- The guard fetches `package.json` at the PR's base and head SHAs through the
  contents API and compares `jq -S .peerDependencies` output. If the fetch
  fails, it reports `changed=true` (conservative: stay manual).
- Grouped majors stay manual because the action reports the group's highest
  bump.
- The condition also covers the `github-actions` ecosystem updates, which is
  acceptable: a broken action pin goes red on the same required check.
- Verification: the guard is dry-run locally against two copies of
  `package.json`; live verification happens on the first Dependabot PR after
  merge (the workflow only runs for `dependabot[bot]`).

## Part 3 — `.nvmrc` tracks the newest Node LTS

### Approaches

| Approach                                                             | Trade-off                                                              | Verdict    |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------- |
| Weekly Action that reads `nodejs.org/dist/index.json` and opens a PR | No new service or secret; exact pin; a human still merges              | **Picked** |
| Renovate with its `nodenv` manager                                   | Declarative, but a second bot alongside Dependabot for one file        | Rejected   |
| `.nvmrc` = `lts/*`, resolved at run time                             | Zero maintenance; CI stops being reproducible and local/CI can diverge | Rejected   |

### Design

- New `.github/workflows/nvmrc.yml`, triggered by `schedule` (Mondays 06:00
  UTC) and `workflow_dispatch`, with `concurrency: nvmrc`.
- Picks `[.[] | select(.lts != false)][0].version` from `index.json` and
  strips the leading `v`. Verified locally against the live index: `26.13.1`.
- If `.nvmrc` already matches, the run ends without a PR.
- Otherwise it commits on `chore/nvmrc-<version>`, pushes, and opens a PR
  with `GITHUB_TOKEN` (no secrets). Branch-per-version, because a push made
  with `GITHUB_TOKEN` to an existing PR branch does not re-trigger CI; a new
  PR does. Open `chore/nvmrc-*` PRs for older versions get closed as
  superseded.
- Commit message `build: track Node.js LTS <version>`; release-please does not
  cut a release for it.
- The PR needs a manual workflow approval before its checks run (same
  `action_required` behaviour as release-please's PR; documented in the
  workflow comments). A human merges it.
- The same PR bumps `.nvmrc` from `24.18.0` to `26.13.1`, so CI proves Node
  26 on real work. Node 26 is not installed locally, so that proof is CI's,
  not this machine's; if it fails, the workflow lands and the bump waits.

## Delivery

Two PRs, in this order, never on `main`:

1. `fix: support msw 3 alongside msw 2` — Part 1 (releases `0.3.1`).
2. `ci: automate dependency upkeep` — Parts 2 and 3.

## Verification

- `npm test`, `npm run coverage`, `npm run typecheck`, `npm run lint`,
  `npm run format:check`, `npm run build` on msw 3.
- The new CI step run locally (done in design: 71/71 with msw 2.15.0).
- `npx prettier --check .` covers the YAML; GitHub's parser is the final
  syntax check when the PR opens.
- `.nvmrc` selection command run locally (done: `26.13.1`).
- Peer guard logic run locally on an unchanged and a changed copy.

## Left to the builder

- Whether the measured-foundations section is #13 or an appendix; it must keep

- Exact LTS workflow shell, as long as the branch-per-version and no-secret
  constraints hold.
