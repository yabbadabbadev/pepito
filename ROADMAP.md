# Roadmap

What's deliberately deferred, with the reason, so a trimmed scope doesn't
get mistaken for an oversight.

| Deferred                                                   | Why                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Traffic recording and replay                               | Solves a different problem (fixtures), and it isn't clear it belongs in the same package                                                                                                                                                                           |
| Network snapshots                                          | Depends on solving deterministic request ordering first                                                                                                                                                                                                            |
| GraphQL                                                    | MSW supports it through a different API (`graphql.query`); it deserves its own design, not a patch                                                                                                                                                                 |
| WebSocket and SSE                                          | The current registry assumes request-response; persistent streams need a different model                                                                                                                                                                           |
| A dedicated `render` helper                                | `vitest-browser-react` already provides one; wrapping it would add a layer to maintain                                                                                                                                                                             |
| `QUERY` support in handlers                                | MSW 2.15 doesn't expose it; today it's covered by declaring `http.all` and filtering                                                                                                                                                                               |
| Header assertions                                          | Easy to add, but no real use case yet                                                                                                                                                                                                                              |
| A `configure()` for global defaults                        | What the previous generation of network-testing tools solved for dissolves here: the host belongs to the handler (cross-origin verified) and startup passes straight through `setupNetwork`; revisit if a real default shows up — candidate: the matchers' timeout |
| A handler builder (`get().returns()`)                      | Sugar that would produce ordinary MSW handlers; can be added without breaking anyone if verbosity starts hurting in real suites                                                                                                                                    |
| A named `scenario()`                                       | Shared setup goes through named setup helpers, like fixtures; revisit only if those fall short                                                                                                                                                                     |
| Storage seeding at mount time                              | Doesn't need an API: storage is real and `setItem` before mounting works as-is; recipe in the README                                                                                                                                                               |
| A guard against calling `setupNetwork()` twice in one file | Today the last call silently wins (it overwrites the registered context); no real use case triggering it yet — revisit if a real bug of that kind shows up                                                                                                         |
| An order assertion between identical calls                 | The registry is already chronological (`traffic-registry.ts` keeps a `Map` in insertion order); it could be exposed without a redesign, but there's no matcher for it today — `toHaveRespondedWith` finds its entry by content, not by position                    |
| Trusted publishing (OIDC, no token)                        | Deferred until 0.1.0 exists on npm — it's configured on npmjs.com on top of an already-published package; once it exists, it replaces the token                                                                                                                    |
| Provenance publishing (`--provenance`)                     | Deferred until this repo goes public — the registry rejects provenance from private source repositories (E422 "Only public source repositories are supported", measured on the v0.1.0 publish); re-enable the flag and the `id-token: write` permission then       |
| Full English translation                                   | **Done** — completed by this migration (2026-08-17): docs, TSDoc, comments, test names and failure messages are now English throughout this repo                                                                                                                   |
