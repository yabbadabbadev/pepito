# Roadmap

Lo aplazado a propósito, con el motivo, para que un alcance recortado no se
confunda con un olvido.

| Aplazado                                                 | Por qué                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grabación y replay de tráfico                            | Resuelve un problema distinto (fixtures), y no está claro que sea del mismo paquete                                                                                                                                                                                     |
| Snapshots de red                                         | Depende de resolver antes el orden determinista de las peticiones                                                                                                                                                                                                       |
| GraphQL                                                  | MSW lo soporta con otra API (`graphql.query`); merece su propio diseño, no un parche                                                                                                                                                                                    |
| WebSocket y SSE                                          | El registro actual asume petición-respuesta; los flujos persistentes necesitan otro modelo                                                                                                                                                                              |
| Helper de `render` propio                                | `vitest-browser-react` ya lo da; envolverlo añadiría una capa que mantener                                                                                                                                                                                              |
| Soporte de `QUERY` en los handlers                       | MSW 2.15 no lo expone; hoy se cubre declarando `http.all` y filtrando                                                                                                                                                                                                   |
| Aserciones sobre cabeceras                               | Fáciles de añadir, pero sin caso de uso real todavía                                                                                                                                                                                                                    |
| `configure()` de defaults globales                       | Lo que resolvía la generación anterior de herramientas de test de red se disuelve: el host es del handler (cross-origin verificado) y el arranque pasa tal cual por `setupNetwork`; se revisará si aparece un default real, candidato: el timeout de los matchers       |
| Builder de handlers (`get().returns()`)                  | Azúcar que produciría handlers MSW normales; se añade sin romper a nadie si la verbosidad duele en suites reales                                                                                                                                                        |
| `scenario()` con nombre                                  | El arreglo compartido va por helpers de setup con nombre, como los fixtures; se revisará solo si se quedan cortos                                                                                                                                                       |
| Siembra de storage en el montaje                         | No necesita API: el almacenamiento es real y `setItem` antes de montar funciona tal cual; receta en el README                                                                                                                                                           |
| Guarda contra doble `setupNetwork()` en el mismo fichero | Hoy gana la última llamada en silencio (pisa el contexto registrado); sin caso de uso real que lo dispare todavía — se revisará si aparece un bug real de ese tipo                                                                                                      |
| Aserción de orden entre llamadas idénticas               | El registro ya es cronológico (`traffic-registry.ts` guarda un `Map` en orden de inserción); se expondría sin rediseño, pero no hay matcher hoy — `toHaveRespondedWith` encuentra su entrada por contenido, no por posición                                             |
| Trusted publishing (OIDC, sin token)                     | Aplazado: se configura en npmjs sobre un paquete ya publicado; cuando exista la 0.1.0, sustituye al token                                                                                                                                                               |
| Traducción íntegra al inglés                             | La 0.1.0 valida el paquete con consumidores cercanos; difundirlo fuera exige inglés en README/CONTRIBUTING/CHANGELOG, TSDoc, comentarios y nombres de test — y en los mensajes de fallo, que son producto: su traducción es un cambio visible que merece versión propia |
